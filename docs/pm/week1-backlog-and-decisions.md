## 6. Ритъм на работа и Definition of Done

- **Дни 1–2:** кратка среща (15 мин.), съгласуван MVP и отговорници, преглед на интерфейсите, блокиращите рискове.
- **Дни 3–4:** реален end-to-end поток и ранен публичен deployment smoke; PM отбелязва само доказани резултати.
- **Дни 5–6:** натоварване, сигурност, SLO отчет, демо и кратък преглед с екипа.

За задачи по сигурността се изисква отделно доказателство: повторим security тест (или конкретен CI run), контролирана проверка на отказите и role/ownership сценарии. Реалният Worker Sandbox трябва да е внедрен и проверен с отрицателни тестове, преди да се счита P0 `SEC-01` за приключена.

**Изрично за ENG-01/02 и SEC-01:** 37 unit + 10 Docker теста са важен локален резултат, но `DONE` изисква публикуван и прегледан код, свързани реални Redis/Judge API услуги, сигурна service identity, реално записан резултат и Security приемане на sandbox. При недостъпен Docker/ API трябва да има повторен опит, не грешка на студента.

Всяко Issue е `Done` само ако: има code/doc review според правилата на екипа; има изпълним тест/демонстрация; има доказателство (линк, лог без тайни, screenshot, отчет); няма неприет блокер по сигурността; PM е актуализирал статуса в продуктовия отчет.
