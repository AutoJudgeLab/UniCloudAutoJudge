# Worker transport

**Status: implemented in judge-api and judge-worker. Disabled on the API until explicitly configured.**
The routes connect private source and sealed tests to the Docker grader and transactional result
service. Integration tests cover real PostgreSQL, MinIO, Redis and Java execution in Docker, plus
authentication, lease contention, retries and hidden-result redaction.

## Configuration

| Process | Variable | Default / meaning |
| --- | --- | --- |
| API | `WORKER_TRANSPORT_ENABLED` | `false`; set `true` to accept worker requests |
| Both | `JUDGE_WORKER_TOKEN` | Same independently generated service secret |
| API | `WORKER_ATTEMPT_LEASE` | `4m`; validated between 1 second and 24 hours |
| Worker | `JUDGE_API_BASE_URL` | `http://localhost:8080`; use HTTPS outside local development |
| Worker | `WORKER_RECLAIM_IDLE` | `5m`; refreshed while a consumer is working |

Generate the credential once, e.g. `openssl rand -hex 32`, and supply the same value to both processes.
Never commit it or reuse a student/admin JWT. Enabled API startup rejects missing, short or malformed
credentials; accepted credentials contain 43–128 URL-safe characters. The worker needs Redis access
and this token, not database/S3 credentials or JWT signing keys.

The Compose API profile forwards these settings. On Kubernetes, provide `judge-worker-token` in
`judge-api-secrets` before enabling transport. Public ingress must exclude `/internal/worker/**`;
these routes belong on the private worker connection. They are omitted from OpenAPI.

## Local worker with the frontend

With Compose infrastructure/API on localhost, set these in the root `.env`:

```dotenv
WORKER_TRANSPORT_ENABLED=true
JUDGE_API_BASE_URL=http://localhost:8081
JUDGE_WORKER_TOKEN=<independently-generated-service-secret>
WORKER_CONCURRENCY=1
WORKER_CONSUMER_NAME=judge-local
```

Keep the existing Redis connection settings, then recreate the API so it receives
the same token. Prepare all [worker toolchain images](../services/judge-worker/README.md#supported-languages)
and start the worker from the repository root:

```sh
docker compose --env-file .env -f infrastructure/docker/compose.yml --profile api up -d --build --wait
mvn -pl services/judge-worker -am package -DskipTests
python3 infrastructure/operations/run-local-worker.py
```

The launcher reads `.env` without executing shell code and passes only worker/Redis
settings plus the API URL/token. Portal, database and S3 credentials are excluded.
It runs in the foreground (Ctrl+C to stop), using `.local/worker-work` for temporary
files. Docker must be running. With the frontend on port 5173, a STUDENT can upload
to a published assignment and watch its evaluation; an ADMIN account cannot submit
on a student's behalf. A stopped worker leaves new submissions pending.

## Why HTTP through judge-api

The worker runs untrusted code, so it gets no PostgreSQL or MinIO credentials. judge-api already owns
the things it needs: private source objects and `EvaluationCompletionService`. Internal routes
provide begin, heartbeat and completion.

## Evaluator identity

- The worker sends `Authorization: Bearer <JUDGE_WORKER_TOKEN>`.
- judge-api maps a valid evaluator credential to the single authority `EVALUATION_WRITE` and to nothing
  else. Local user JWTs must keep not granting it.
- The routes live under `/internal/worker/**` and must not be reachable from the public ingress.
- A separate Spring Security filter chain checks SHA-256 digests of opaque service tokens in constant
  time. User JWTs are rejected here; worker tokens are rejected on public user/admin routes.
- Transport is stateless. Job responses use `Cache-Control: no-store`.
- Rotate the credential in both processes together and restart them. Invalid/disabled credentials
  return `401` and leave events pending. Per-worker credentials, automatic rotation and mTLS remain
  possible future extensions.

## 1. Begin an attempt

`POST /internal/worker/v1/submissions/{submissionId}/attempts`

```json
{ "attemptId": "uuid generated by the worker", "eventId": "uuid of the delivered outbox event" }
```

The API first checks that `eventId` identifies a real `SUBMISSION_CREATED` v1 outbox event for this
submission and sealed revision. Unknown/mismatched events return `422`. The source key comes only
from stored metadata. Downloads are bounded by the accepted size and checked against its SHA-256;
unavailable/corrupt source returns `503` and does not claim a new attempt.

judge-api decides, inside the submission row lock:

| Submission state | Action | Response |
| --- | --- | --- |
| `PENDING` | `begin(submissionId, attemptId, currentVersion)` | `200` with the job |
| `RUNNING`, same `attemptId` | idempotent replay | `200` with the job |
| `RUNNING`, other attempt, persisted lease still live | none | `409` |
| `RUNNING`, other attempt, lease expired | `begin(...)` replaces the abandoned attempt | `200` with the job |
| `COMPLETED` (or any state that cannot start) | none | `204` |
| Unknown submission | none | `404` |

The lease is what replaces a crashed worker without letting a duplicate delivery steal a live attempt.
The default lease is 4 minutes. Begin and same-attempt replay renew it without
incrementing the replayed attempt count. The worker renews during compilation,
test execution and result upload; leases no longer need to exceed total grading time.

`POST /internal/worker/v1/submissions/{submissionId}/attempts/{attemptId}/heartbeat`
returns `200 {"leaseMillis":240000}`. The worker renews every third of that duration.
The API locks the submission and refuses obsolete or completed attempts with 409.
Redis idle time is refreshed separately, only while the same consumer owns the record.
Choose lease/idle intervals comfortably above network latency and transient pauses.
Upgrade the API before workers, then restart all older workers: they cannot renew leases.

`200` body:

```json
{
  "submissionId": "uuid",
  "attemptId": "uuid",
  "assignmentRevisionId": "uuid",
  "programmingLanguage": "JAVA",
  "originalFilename": "Main.java",
  "source": "public class Main { ... }",
  "timeLimitMs": null,
  "memoryLimitMb": null,
  "tests": [
    { "testCaseId": "uuid", "inputData": "2 3\n", "expectedOutput": "5\n", "points": 100, "executionOrder": 0 }
  ]
}
```

- `tests` are those of the submission's **sealed revision**, hidden ones included, never the current
  editable configuration.
- `source` is the stored object as text; uploads are already validated as UTF-8.
- `timeLimitMs` and `memoryLimitMb` are optional. Assignments have no limit fields today, so the worker
  uses its own defaults when they are null or absent.
- The response carries hidden tests and student source: no caching, no request/response body logging.

## 2. Store the result

`POST /internal/worker/v1/submissions/{submissionId}/attempts/{attemptId}/result`

The body is `EvaluationCompletion` without the two IDs that are already in the path:

```json
{
  "verdict": "WRONG_ANSWER",
  "totalScore": "40",
  "passedTests": 1,
  "totalTests": 2,
  "executionTimeMs": 117,
  "tests": [
    { "testCaseId": "uuid", "status": "ACCEPTED", "awardedPoints": "40", "executionTimeMs": 117, "actualOutput": "5\n" },
    { "testCaseId": "uuid", "status": "WRONG_ANSWER", "awardedPoints": "0", "executionTimeMs": 63, "actualOutput": "0\n" }
  ]
}
```

Scores are decimal strings so no JSON number parser rounds them. `actualOutput` is at most 16 KiB by
default (API limit 64 KiB) and never contains NUL.

| Outcome in `EvaluationCompletionService.complete` | Response | Worker reaction |
| --- | --- | --- |
| Stored, or an identical replay of a stored report | `204` | acknowledge the event |
| Stale attempt, conflicting replay | `409` | drop the result, leave pending; the replacement owns completion |
| Report fails semantic validation | `422` | dead-letter the event; this is a worker bug |
| Malformed JSON, missing required fields, unknown fields | `400` | dead-letter the event |
| Anything temporary | `5xx` | retry the upload, then leave the event pending |

The worker's reports are built to satisfy `validate(...)`: every configured test is reported unless the
verdict is `COMPILATION_ERROR` (no tests) or `INTERNAL_ERROR` (possibly none), accepted tests carry their
configured points, and the summary verdict is the first failing test's status.

## Delivery and remaining limitations

An ACK follows a stored result or an API response indicating an already terminal submission.
A stale worker must not acknowledge a message being processed by its replacement. Temporary HTTP
failures and busy leases stay pending even after `WORKER_MAX_DELIVERIES`; only the processor can
finalize grading failures as `INTERNAL_ERROR`. Invalid events/reports are parked for operator repair.
See [recovery](reliability.md) for replay after Redis loss or stream trimming.

Per-assignment time/memory limits and a compiler-diagnostic field remain future work. Jobs currently
carry null limits and use worker defaults. [All ten API languages](../services/judge-worker/README.md#supported-languages)
have evaluators; disabling a language must be coordinated with API acceptance. The service token
grants evaluation access across submissions, not user or administrator privileges.

## Executable worker configuration verification

The shipped-YAML binding test also checks that Docker sandbox and grading limits
are populated when Spring constructs the worker. The sandbox record has an explicit
constructor-binding annotation because it provides a second convenience constructor.
Missing nested configuration now fails startup instead of accepting jobs and failing
later. This was verified with the executable JAR and real Portal/UI submissions;
a previously pending attempt was recovered and completed after its lease expired.
